---
title: Reconstructing Modeller
description: How capabilities move from the legacy implementation into the successor.
---

The successor is not a directory-level refactor of the legacy repository. Each
capability is reconsidered at an explicit module seam, then reused, adapted, or
rewritten according to the desired behaviour.

1. Record existing behaviour and tests.
2. Confirm the behaviour that should survive.
3. Define the new module interface and invariants.
4. Implement behind that seam.
5. Verify the interface with acceptance tests.
6. Mark the legacy capability as superseded.
